Rate Limit Lab

Ledgerline is a pretend bank with a public API. Like a real bank, it can't let anyone send unlimited requests, so it uses four different rate limiting rules, each suited to a different job. Press the buttons below and watch each rule react in real time. All money here is fake.

1Get a test API key

An API key is how the bank knows who's calling. One click creates a test customer with two accounts (Checking $5,000 and Savings $20,000) and a key.

1You're set up

Your key is saved in this browser tab. Everything below uses it.

2Try each rule

Everyday requestsToken bucket

You get a cup of 10 tokens. Every request spends one. The cup refills with 2 tokens every second. Empty cup = request blocked.

Why a bank uses it: a banking app sends a burst of requests when you open it, then goes quiet. This allows the burst but stops anyone hammering the bank non-stop.

Money transfersSliding window

At most 5 transfers out of an account in any 60 seconds. The 60 seconds always means "the last 60 seconds from now", so the limit can't be dodged by timing.

Why a bank uses it: if a thief gets into an account, they try to drain it quickly. This caps how fast money can leave.

Transfers from Checking in the last 60 s–

Payroll payoutsLeaky bucket

Payouts to other banks join a queue of 20 that sends out 1 payout per second, always at the same steady pace. If the queue is full, new payouts are turned away.

Why a bank uses it: the payment network between banks only accepts a steady trickle of payments. A company paying 25 staff at once gets them sent smoothly instead of all at once.

Payouts waiting in the queue–

Daily allowanceFixed window

The free plan includes 1,000 requests per day. The count goes back to zero at midnight UTC, so you always know when it resets.

Why a bank uses it: it's how API plans are sold and billed ("1,000 calls a day"). Every request you make above counts towards it.

Used today–

Safe retriesIdempotency key

Each transfer carries a unique ID. If the same transfer is sent again (say the network dropped and the app retried), the bank sees the ID, doesn't move the money again, and replies with the original answer.

Why a bank uses it: without it, a retry after a timeout could pay someone twice.

allowed queued / replayed blocked (HTTP 429 "Too Many Requests")
